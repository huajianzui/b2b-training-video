# OVM 实测后的制作体验改版

状态：实施中。基线：`aa22f15`；分支：`fix/runtime-entries`。用户于 2026-10-14 授权按六项结论分批修改、回归、复审，最后再用 OVM 实测。仅本地实现与提交；不推送，不修改 OVM 业务代码。

## 目标、证据与边界

让 Agent 在准备阶段集中取得必要信息，按已确认范围完成面向业务用户的培训视频、手册及问题报告。减少等待、逐项配置和返工；实际提交的阶段授权、数据范围与故障证据仍须可靠。

上轮 OVM 两份视频共 14 分 43 秒，从任务到交付历时 5 小时 50 分 55 秒；其中最大无活动回合间隔 1 小时 20 分 52 秒，不能全部归为计算耗时。19 次结构化答复之外还有页面点击和普通消息。44 项清单中选中 30 项、20 项写功能需检查 40 个阶段设置。主要证据保存在 OVM `.training-video/output/trial/review-result.md`；本计划只保留可复用结论，不复制业务数据或凭据。

已确认边界：演练可真实提交，演练与正式录制分别选择；每次实际写入执行仍需用户确认，Agent 不代点。OVM 使用当前本机开发库，只新增本轮培训数据，不建副本、不改原记录；保留企业微信开关，五类申请只演示至提交前。附件与两种导入须在新一轮范围中明确选择，不能沿用其他写功能的许可。新 OVM 数据方案准备好后集中确认。

## 六项结论与落地

| 结论 | 改版行为 | 验收证据 |
|---|---|---|
| 制作过慢 | 开始前最小依赖/媒体/语音探测；可靠确认和字幕；角色产物隔离；后期更正不重新执行业务；分阶段记录耗时 | 故障在写入前暴露；两个角色互不覆盖；后期命令零业务请求；实际耗时记录 |
| 交互贯穿全程 | 准备阶段集中确认环境、范围、账号数据、文件、语音与阻塞策略；实际提交保留两个明确节点；页面信号自动继续 | 无需另回“已提交”；服务端失败可再次点击；普通恢复不重复询问已决事项 |
| 清单逐项设置繁琐 | 全局/小模块批量设置；演练和录制独立；单项例外可保留、可显式覆盖；显示混合状态与统计 | 仅作用于已勾选可执行写功能；未选择/只读/阻塞项不获写许可；未确认不能执行 |
| 对象与文案不准确 | 业务任务自然衔接；讲清按钮、结果、后续审批；取消实操也解释正常提交路径；制作约束留在内部报告 | 发布前集中审稿；旁白无开关、调试、安全授权等制作说明；未执行结果使用条件语气 |
| 附件与导入缺失 | 文件上传动作；真实模板与最小样本；上传/预检的副作用明确批准；本轮临时文件有清单并适时清理 | 真实浏览器上传；非法/越界文件拒绝；取消不能偷偷上传；两种导入独立覆盖；原文件保留 |
| 阻塞处理与附加产物 | 事先选停止或跳过/文字讲解；依赖场景一并处理；覆盖度区分实操/部分/文字/跳过；交付问题与优化建议 | 不把未完成算全覆盖，不重放状态未知写入；故障归属、复现、证据与建议可追查 |

## 实施顺序与完成标准

1. **可靠性**：修复跨进程环境变量导致确认指纹不同、标点边界空字幕、确认按钮失败不可重试、请求诊断丢失查询信息。先补真实失败回归，再修复。保持精确请求匹配，不记录查询值或凭据。
2. **制作体验**：精简入口与两个现有提示词；增加集中准备单、阻塞与问题报告范例。实现清单批量操作、前置探测、角色输出隔离及明确的纯后期入口；沿用既有阶段与产物校验，不另造流程框架。文档与运行行为同步，补 CLI、跨角色、零业务重放、UI 行为回归。
3. **文件处理**：在现有动作和请求授权中增加上传能力、文件来源与临时清理约束；确认页展示上传/预检副作用。只批准精确接口，不能把写入标为只读。复用现有模板下载方式，不实现通用 Excel 编辑器、服务端数据回滚或自动删库。补必填上传、导入模板样本、未批准副作用和本地清理回归。
4. **复审与实测**：先在隔离夹具验证关键闭环，再运行完整测试（零跳过）和桌面确认页验收。独立复审业务完整性与技术风险。升级 OVM runtime 保留用户脚本/登录态/旧成品，形成集中试运行清单及新数据范围后确认，执行实测，报告覆盖、耗时、人工介入与限制。

每批验证通过且归属清楚后本地提交；复审发现阻塞问题先修复。全量 OVM 实测不能以旧视频、模拟成功或部分回归替代。若必须等待用户点击提交，保留具体可审查范围和正在等待的进程。

## 体量控制

基线 Git 跟踪文件 66 个、约 476 KiB、8,451 行；SKILL.md 184 行，两个提示词 140 行。依赖、字体和视频不计入 Skill 源码体量。

主入口保留目标、顺序、授权边界与交付标准，条件细节放现有 prompts 或少量按需参考；删除重复规定再增加要求。保持一个 Skill，不增加常驻平台、任务调度器或通用工作流引擎。每批记录主入口、运行代码、测试和参考文档的净变化；体量增长应对应可验收能力。最终主入口不超过原有行数；测试不为压体量删减。

## 方案复核与实施记录

- 初稿已依据现有 requests/confirmation/pipeline/produce/compose 和 OVM 实测报告整理；下一步独立检查批量授权、部分覆盖、文件副作用及后期复用的边界。
- 兼容原则：现有有效脚本继续可执行；新增功能显式配置，缺失字段沿用原来的停止行为。需要迁移的缓存给出具体命令，不静默复用不匹配的来源。
- 业务独立评审已完成；采纳：固定禁止提交的功能不能被“覆盖例外”改变；上传/预检与最终提交分别批准，最终取消仍可能需要上传阶段确认；覆盖表固定原批准范围，注明批准取消已完成但未实际提交；业务开关可以讲，制作控制开关不进入旁白。
- 角色隔离复用既有安装能力：一角色一工具目录，依赖可通过 PW_WORKSPACE 复用，不增加 output 路由系统。跨角色数据依赖仍由同一准备单记录。纯后期入口只接受已验证的原始录制素材及允许修改的文案字段，音频超出原时间窗时拒绝，不重放业务。
