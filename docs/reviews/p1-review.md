最后复审还补齐了以下相关缺口：

- 场景 YAML 禁止填写 `writeMode`、`writeRequests`、`expectAt`、`endExpect` 内部字段；授权只能由已确认功能和 ending 派生。运行时 grant 同时校验已声明接口与本阶段批准接口。
- 已知 GET 写路径的 HEAD 不能借用默认只读方法。内部字段、HEAD 和非法 grant 三个新增回归在修复前全部失败，修复后通过。HEAD 用例在修前实际观察到后台写入计数为 1。
- HTTP API 重定向逐跳检查，跨来源不得借用许可；未知 WebSocket 不连接服务器，只读连接明确列入清单。提交已到后台但响应断开时报告未知状态，提示核对数据，不自动重试。
- 场景范围展开完整 continue 组，组首、组中、组尾均验证收尾；演练和正式素材分目录，正式手册拒绝演练素材。
- 确认页显示真正执行的脚本标题、文件名、完整路径、阶段、环境和功能；清单 A 与执行脚本 B 不匹配时警示，确认后的报告只属于 B。

## P1 阶段剩余 P2（后续已修复）

当时按用户要求只修 P1，以下问题保留；现已逐项关闭，复现和回归证据见 [P2 复审](p2-review.md)：

1. **同 ID 功能业务描述变化未撤销旧确认。** [features.js](../../scripts/features.js) 的 mergeFresh 只依据新增、删除、kind 或 writeRequests 变化撤销确认。permission、when、requires 等变化仍可能显示已确认，让脚本基于旧用户判断继续编写。需要针对这些变化建立重新确认口径；写接口及 kind 的授权变化已经覆盖。
2. **最终视频验收仍不充分。** [mp4info.js](../../scripts/tools/mp4info.js) 没有要求必须存在 moov/视频轨，空文件也可能返回正常；[intro.py](../../scripts/intro.py) 未使用 verify(final) 的返回值，缺 Node 或超时还会跳过校验；[produce.js](../../scripts/produce.js) 片头失败仍可输出正片并显示完成。存在故障被交付结果掩盖的条件，需要单独补齐最终成品验收。
3. **带片头的外置字幕时间未平移。** 正片 `subs.srt` 直接作为最终字幕交付，片头拼接后的时间轴与正片字幕不一致。视频内已烧录字幕不受这一外置文件偏移影响。
4. **网页任务缺人工登录完成按钮。** [login.js](../../scripts/login.js) 默认 start 为 manual，只在 TTY 接受回车；网页任务的子进程没有 TTY，当前 features.html 只处理 dataWait，没有处理 loginWait。人工登录后网页任务可能一直等待。直接交互终端可按回车；本次真实登录回归使用明确配置的 start:auto，没有验收网页人工登录完成流程。

## 未覆盖边界与复用要求

- P1 阶段没有访问真实业务系统，没有验证具体权限、系统专属数据复位、微软在线配音及片头片尾。后续 P2 已补充真实本地片头片尾拼接与字幕验收；真实系统和在线配音仍需集成验证。任何真实提交前仍需用户核对本轮数据。
- 客户端不能推断未知 GET 的写语义。必须从业务代码列出所有 GET 写接口和实际 API 来源；已知 GET 的 HEAD 保护不代表未知 HEAD 业务语义已被识别。
- 共享 GraphQL/RPC 路径同时承担查询和修改时，当前路径规则拒绝读写歧义。不要将该共享 POST 整体列为只读；需可区分的接口或后续专门适配。WebSocket 写通道暂不支持。
- Service Worker 被关闭。HTTP API 重定向最多按 Playwright 默认 20 跳逐跳检查；页面导航重定向明确失败，需核实并配置最终页面地址。具有这些机制的业务系统要单独演练。
- 外部 Origin 的服务端回归证明协议拒绝逻辑；没有证明现代浏览器本地网络保护可被绕过。原版跨站风险是否能在特定浏览器触发，取决于其本地网络访问策略。
- 死进程的输出锁不会自动回收。核实没有运行中的任务后只移除该锁文件，避免自动抢占破坏来源记录。旧 JSON 和旧缓存明确要求从 YAML 重新生成。

修复经验和接口口径已落在 [P1 修复计划](../plans/p1-hardening.md)、[SKILL.md](../../SKILL.md)、场景/盘点提示及回归测试中。之后修改收尾、请求策略或阶段顺序时，优先复用这些回归；普通出片成功不能代替权限、重复执行和续跑验证。新会话自动发现这些规则的行为未另行验收。
