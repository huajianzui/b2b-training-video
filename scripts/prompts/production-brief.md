# 集中准备与验收

在首次准备数据之前使用。先读项目规则、代码和已有授权，能查到的信息自己查；只把仍需用户决定的内容合成一次问题。已确认选择直接引用，不重复询问。

## 一次确认的准备单

在工具目录 `output/brief.md` 填好具体建议，再交用户调整：

| 决策 | 已核实内容与推荐方案 |
|---|---|
| 受众与范围 | 业务角色、模块/小模块、必要前提、计划时长；以功能任务组织，不以代码页面数量凑清单 |
| 环境与数据 | 实际 URL、是否允许测试数据；角色与现有资格；**本片独占的数据基线**（优先独立项目或独立任务库；多份脚本共用同一库、或同一项目的同一年度时，新建会占用唯一名额、先出片的一方还会改写后一方的记录，只能严格串行且顺序敏感）；本轮新增/编辑/归档的具体记录范围，演练与录制各用哪些数据；**重录复位方式**与不可逆目标（归档、停用常不可回滚，新建类操作重录会产生同名重复记录，需先改名或让位） |
| 批量策略 | 两轮分别提交还是取消；按小模块应用默认方式；通知、删除、归档、导入等拿不准的列为例外；标清尚未批准项 |
| 文件与导入 | 是否制作小附件、允许格式/大小/个数；普通导入和首次初始化分别是否做；模板来源、最小样本行、上传/预检是否写入或发送通知、清理范围 |
| 配音 | 语音提供方与发送的内容范围；默认 edge-tts 会把文本发到微软在线服务；开场/结束语、业务术语一起核对 |
| 阻塞处理 | 需要完整覆盖则停止告知；允许继续则记录跳过/仅文字讲解及受影响的依赖功能；哪些关键小模块仍须停止 |

普通已批准行为不再逐项问。真实提交只保留预告的演练和正式录制确认节点；页面确认后等执行器自动继续，不要求再回复“已提交”。新副作用、超出数据范围或状态未知才补充决策。

## 旁白集中审稿

先整理全篇旁白与业务顺序，再合成语音。Agent 自查后，把确有业务歧义的句子集中给用户；正常文案调整自己完成。读音抽听合并为一次有位置的短样本，优先放在正式录制前，不逐词打断。

- 观众是系统使用者。每段承接上一项业务：创建后维护信息、下发后跟踪进度、调整后查看结果。
- 说清入口、所填信息、按钮、结果在哪里，以及审批人和生效条件；依据当前代码/配置/界面核实，不能凭旧文档猜节点。
- 实操取消也先讲正常路径，例如：“填写完成后点击提交，申请将依次由项目经理和负责人审批，通过后更新任务。现在返回列表。”只有已核实这些节点时才能这样写。
- 未执行的结果用“会、将、通过后”，不能说“已经成功”。必要时用“本段说明后续流程”标明文字讲解，不能让观众以为画面完成了提交。
- 不解释制作时调整的通知开关、接口、授权、测试环境、调试与避免污染数据；这些是制作记录。已选业务界面的通知选项仍应讲清用途和结果，不把技术实现或泛化说教当培训内容。
- 手册采用相同业务口径。权限不匹配时说明“此操作由具有相应权限的负责人办理”，不要把演示账号的配置作为培训内容。

## 阻塞与覆盖

运行错误先保留原报告和必要现场，检查是业务系统、工具、环境还是脚本问题。只有查明原因或前提发生变化才再次尝试；不连续盲重试。全局依赖（登录、语音、媒体工具）故障先修复，不能伪造成功音频或视频。

发生写入或响应未知时先用只读方式核对当前状态，不自动重复操作或回滚。新建前置记录失败，其后的编辑/归档场景也不可执行，更不能换原有业务记录顶替。

用户选择继续时，保留原批准范围。在 `output/review-result.md` 用稳定功能 ID 逐项记录：实操完成、部分实操并讲解、仅文字讲解、跳过。保留阻塞原因与后续讲解依据，视频、手册、覆盖表三者一致；不能通过取消勾选或 `--allow-uncovered` 报全覆盖。未执行功能不伪造成功断言、步骤截图或结果。

## 问题与优化建议（与覆盖表共用一份报告）

| ID | 归属/类型 | 影响 | 功能/环境/角色 | 预期与实际 | 最小复现/证据 | 状态与建议 |
|---|---|---|---|---|---|---|
| 示例 | 业务系统/待核实阻塞 | 无法完成提交 | 功能 ID、测试环境、角色 | 描述具体差异 | 原日志/截图位置，不存凭据 | 待核实；下一项检查 |

类型区分已复现 bug、待核实阻塞、交互建议、视觉或文案建议；证据不足不能给业务系统定性为 bug。交互或视觉建议说明哪个控件影响什么任务，不用“很丑”等无依据评价。普通建议集中交付；阻塞和授权问题及时告知。只收集本次演示顺带发现的事实，不宣称完成全面 QA，也不自动修改业务代码。

## 效率与清理

记录准备、语音、演练、录制、合成的起止与耗时；人工等待单列，另记确认次数、故障重试与覆盖度。对比相同范围的片长和耗时，不把整段墙钟时间说成模型计算时间。

临时附件在本轮专用目录，记录来源、用途、依赖阶段与实际生成文件路径。下载的原模板与用户原文件保留，填写时另存副本。演练、录制和获准重试都不再需要后，仅删除清单中的本轮临时文件；失败时先保留恢复所需材料。最终视频、手册、字幕及最小问题证据保留。服务端附件、导入审计和业务记录不是本地临时文件，按明确获准的数据清理方案处理。
