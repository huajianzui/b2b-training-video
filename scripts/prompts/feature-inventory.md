# 功能盘点提示词

用途：读业务系统代码，产出一个模块的功能清单（`<名字>.features.yaml`），交给用户在确认页勾选。
占位符：`{{module}}` 模块名、`{{system}}` 系统名、`{{code}}` 代码目录、`{{account}}` 演示账号、`{{script}}` 对应演示脚本文件名、`{{model}}` 模型名、`{{date}}` 日期、`{{out}}` 输出文件。

---

你在为「B 端系统培训视频自动生成工具」盘点功能。工具会按功能清单用 Playwright 操作真实系统录制培训视频（中文旁白），并生成 Word 操作手册。功能清单决定这个模块演示哪些功能，用户会在勾选页确认。清单要完整，但每一项都应该是值得在培训视频里讲的东西。

## 目标

- 系统：{{system}}
- 代码：{{code}}（只读这个目录）
- 模块：**{{module}}**，包括从它能进入的所有下级页面、弹窗、抽屉
- 演示账号：{{account}}

## 限制

- 只读代码。不修改文件、不启动服务、不操作浏览器。
- 只在 {{code}} 内搜索和读取。
- 唯一要写的文件：{{out}}

## 判断规则

1. **一个功能 = 用户完成的一件事。** 同一个操作有多个入口（如明细页、维护页、申请记录页都能发起同一种申请）只算一项：挑用户最常用的入口作为它的 page，其他入口写进 desc（「也可以从 XX 发起」）。
2. **只为某个操作服务的页面不单列。** 点按钮后跳转、填完就回去的页面（申请表单页、某条申请的详情页）属于发起它的那个功能，不进 pages。pages 放用户会停留、在上面做多种操作的页面——包括从列表点进去的明细页、维护页。
3. **成对的开关合并。** 启用 / 停用、展开 / 收起这类写成一项（name 如「启用 / 停用任务」）。
4. **没资格 ≠ 演示不了。** 演示账号没有权限或业务资格，但入口看得见、点了会显示禁用状态或拒绝提示的，不写 blocked。在 when 里写清：谁有资格、演示账号会看到什么（禁用 / 提示的原文），视频会如实讲「演示账号没有权限，有资格的人会……」。
5. **blocked 只用于什么都展示不出来的情况**：功能未接入、缺少必需文件且没有可演示的部分、代码 bug 导致功能不生效。缺文件但能演示一部分的（如能下载模板、能看导入窗口说明）不写 blocked，在 how 里写清能演示到哪一步。
6. **发现 bug 要写出来。** 界面有控件但逻辑没接上（如切换选项不影响查询）：写 blocked，以「前端 bug：」或「后端 bug：」开头，写清文件和函数。
7. **minor 标记**：操作一眼就会、不值得单独一个场景的（查看空状态的记录、和另一类页面完全相同的重复操作）写 minor: true。不同类型的页面（如项目类 / 非项目类明细）上同一个功能，**每个页面都要列**：用法有差异就在 desc 里写差异；没有差异的后一个标 minor，但不要省略——用户可能只想看其中一类页面的视频。
8. 有学习成本的复杂交互（批量录入窗口里的加行方式、批量设置、预校验等）在 how 里分点讲清楚要演示的环节。
9. 显示条件从模板的 v-if / disabled 和后端校验里找，写进 when。纯技术性的控件（刷新、分页）不列；查询的「重置」并进查询功能。
10. **通用操作标 shared。** 先找出系统的公共组件（如查询栏、表格、行操作菜单、表单弹窗的封装组件，被很多页面引用）。页面上直接由公共组件提供、用法和其他页面完全相同的操作，照样列出，但写 `shared: 查询`（或 表格 / 弹窗），由《系统通用操作》统一讲。判断看用法而不是看组件：查询条件里有本模块特有含义的（如业务阶段分售前、在建、售后），在 desc 里写清各选项含义，手册会列出；查询之外有特殊逻辑的（如联动、远程搜索人员），不标 shared。
11. 一个模块通常 30–45 项。明显超出时，回头检查是否违反了 1–3 条。

## 输出格式（YAML）

```yaml
module: {{module}}
script: {{script}}
generatedBy: {{model}}
generatedAt: {{date}}
confirmedAt: ~                       # 固定写 ~，用户确认后回写
pages:
  - id: list                         # 短英文
    name: 订单列表
    entry: 左侧菜单「业务 › 订单管理」   # 用户怎么进到这个页面，用界面上看得到的文字
    route: /orders
    files: [views/order/OrderListView.vue]
features:
  - id: list.create                  # 页面id.动作，稳定
    page: list
    name: 新增订单
    kind: write                      # read 只读 | write 写数据
    desc: 这个功能是什么；其他入口
    how: 打算怎么演示（一两句，复杂交互分点）
    permission: order:manage         # 代码里的权限标识，没有就省略
    when: 显示 / 可用条件；演示账号没资格时会看到什么
    requires: 演示前提（要什么数据 / 文件）
    blocked: 演示不了的原因           # 只按规则 5、6 写
    minor: true                      # 只按规则 7 写
    shared: 查询                      # 只按规则 10 写
    source: views/order/OrderListView.vue:6
```

不要写 include / writeMode / status（用户确认时回写）。可以用 # 注释按页面分组。

## 完成后返回

1. 文件路径
2. 页面数、功能数（write / blocked / minor / shared 各多少）
3. 发现的 bug（文件、函数、现象）
4. 最不确定的 3–5 个判断及原因
